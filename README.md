# Cloover AI Sales Coach

AI sales co-pilot for Cloover, now with a voice roleplay training mode.

Live app URL:

`https://cloover-challenge-team1-production.up.railway.app`

## What it does

- Takes a postal code, product interest, and optional Cloover blocks.
- Runs quality checks before anything is saved or passed to the LLM.
- Enriches missing data conservatively.
- Stores every enriched session in `knowledge_base/`.
- Generates a grounded sales briefing from the fresh, quality-checked KB.
- Supports voice roleplay with ElevenLabs when available, and a text fallback when it is not.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env
# fill in ANTHROPIC_API_KEY or another supported provider key
# optionally fill in ELEVENLABS_API_KEY and CLOOVER_API_KEY
streamlit run app.py
```

## API provider selection

- If `ANTHROPIC_API_KEY` is set, the app uses Claude Sonnet via LangChain.
- Otherwise, if `GEMINI_API_KEY` is set, it uses Gemini via LangChain.
- Otherwise, if `Z_AI_API_KEY` is set, it uses the configured OpenAI-compatible endpoint such as Featherless.
- If no provider key is present, the app falls back to offline grounded output.

## Vercel

Vercel is not a good fit for this repository in its current form.

- This app is a long-running Streamlit server.
- Vercel does not run arbitrary Docker containers for user apps.
- Vercel serverless functions are request/response oriented and are not suitable for hosting a persistent Streamlit process or a near-realtime voice loop.

If you want to deploy the current app without rewriting the runtime model, use a container-friendly host such as Render, Railway, Fly.io, or Azure App Service.

If you specifically need Vercel, the app would need to be split into:

- a separate frontend for the UI and realtime voice experience
- API routes or another backend service for enrichment and coaching
- a non-Streamlit architecture

## Voice roleplay

- `ELEVENLABS_API_KEY` enables ElevenLabs TTS output and the voice training tab.
- The app is designed to support realtime voice, but also remains runnable without it.
- If realtime transport is unavailable, the roleplay tab falls back to push-to-talk text plus TTS playback.

## Key Benefits / USPs

- **Grounded advice**: every coach reply and briefing is generated from quality-checked, conservative enrichment (geocode, PVGIS, Open-Meteo) so model outputs remain tied to real, auditable data.
- **Installer-first UX**: three-pillar coaching (Market, Offer, Financing) that maps directly to installer talking points and a short live roleplay workflow with microphone push-to-talk and TTS playback.
- **Voice + Text pipeline**: ElevenLabs STT → LLM coach → ElevenLabs TTS for an end-to-end voice training loop (with safe fallbacks when keys or realtime features are unavailable).
- **Deployable container**: Dockerfile included for straightforward deployment to container-friendly hosts (Railway, Render, Fly.io, Azure App Service).
- **Extensible KB**: quality-checked sessions are saved to the knowledge base so you can iterate model prompts, build playbooks, or export transcripts for training.

## Export Briefings to PPTX (quick guide)

You can convert generated briefings into a PPTX slide deck using `python-pptx`. Below is a tiny example you can run locally to convert the `briefing` text shown in the Output tab into a simple slide deck.

1. Install the helper library:

```bash
pip install python-pptx
```

2. Example `briefing_to_pptx.py` script (run from the project root):

```python
from pptx import Presentation

def briefing_to_pptx(text: str, out_path: str = 'briefing.pptx'):
	prs = Presentation()
	# Title slide
	title_slide_layout = prs.slide_layouts[0]
	slide = prs.slides.add_slide(title_slide_layout)
	title = slide.shapes.title
	subtitle = slide.placeholders[1]
	title.text = 'Cloover AI Sales Coach — Briefing'
	subtitle.text = 'Generated by Cloover AI'

	# Split briefing into sections by double-newline for slides
	parts = [p.strip() for p in text.split('\n\n') if p.strip()]
	for part in parts:
		slide = prs.slides.add_slide(prs.slide_layouts[1])
		slide.shapes.title.text = part.split('\n', 1)[0][:60]
		body = slide.shapes.placeholders[1].text_frame
		body.text = part

	prs.save(out_path)

if __name__ == '__main__':
	import sys
	briefing_text = sys.stdin.read() or 'No briefing provided.'
	briefing_to_pptx(briefing_text)
```

Usage example, piping the briefing text into the script:

```bash
# from project root, after you copy the briefing text from the Output tab
echo "$(cat validated_enriched_output.json)" | python briefing_to_pptx.py
```

Note: for nicer slides you can parse the briefing structure (Diagnosis / What to say / Why it works / Next question) and render each part in its own slide. If you'd like, I can add a `Download briefing as PPTX` button directly into the Output tab that uses this approach server-side.

## Notes on quality

The app follows this order strictly:

1. Gather
2. Validate quality
3. Enrich
4. Save to KB
5. Use LLM

Every session records a quality score and conservative enrichment notes.
